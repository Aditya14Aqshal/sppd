Sequence Diagram — Sistem Informasi SPPD Bakesbangpol

Diagram Alur Proses Perjalanan Dinas

Diagram ini menjelaskan alur interaksi antar komponen dalam sistem SPPD mulai dari login, pengajuan, verifikasi, persetujuan, hingga pencetakan.
1. Proses Login
sequenceDiagram
    autonumber
    actor User as Pegawai / Admin / Pimpinan
    participant Browser as Browser
    participant Login as login.php
    participant DB as Database

    User->>Browser: Buka aplikasi SPPD
    Browser->>Login: GET /pages/auth/login.php
    Login-->>Browser: Tampilkan form login

    User->>Browser: Masukkan username & password
    Browser->>Login: POST (username, password)

    Login->>DB: SELECT tb_pengguna + tb_pegawai WHERE username = ?
    DB-->>Login: Hasil query (id, password, role, status, nama)

    alt Username ditemukan & status aktif & password valid
        Login->>Browser: Set session (user_id, role, nama)
        Login->>Browser: Redirect ke /pages/dashboard/
        Browser->>Dashboard: Load dashboard
        Dashboard-->>Browser: Tampilkan statistik & SPPD terbaru
    else Gagal
        Login->>Browser: Tampilkan error "Username atau password salah"
        Browser-->>User: Pesan error ditampilkan
    end
2. Pengajuan SPPD (Oleh Pegawai)
sequenceDiagram
    autonumber
    actor Pegawai as Pegawai
    participant Browser as Browser
    participant Ajukan as ajukan.php
    participant DB as Database

    Pegawai->>Browser: Klik "Ajukan SPPD"
    Browser->>Ajukan: GET /pages/sppd/ajukan.php
    Ajukan->>DB: SELECT data pegawai, jabatan, tujuan, kegiatan, anggaran, komponen biaya
    DB-->>Ajukan: Data pendukung form
    Ajukan-->>Browser: Tampilkan form pengajuan (4 langkah)

    Pegawai->>Browser: Isi form: kegiatan, tujuan, tanggal, anggaran
    Pegawai->>Browser: Klik "Ajukan SPPD"

    alt Validasi form berhasil
        Browser->>Ajukan: POST (id_kegiatan, id_tujuan, id_anggaran, keperluan, tgl_berangkat, tgl_kembali, kendaraan, submit_type)

        alt submit_type = "ajukan"
            Ajukan->>DB: INSERT INTO tb_sppd (status = 'diajukan')
            DB-->>Ajukan: id_sppd baru
            Ajukan->>Browser: Redirect ke detail.php?msg=diajukan
        else submit_type = "draf"
            Ajukan->>DB: INSERT INTO tb_sppd (status = 'draf')
            DB-->>Ajukan: id_sppd baru
            Ajukan->>Browser: Redirect ke detail.php?msg=draf
        end

        Browser-->>Pegawai: Tampilkan detail SPPD dengan status
    else Validasi gagal
        Ajukan->>Browser: Tampilkan error
        Browser-->>Pegawai: Pesan error ditampilkan
    end
3. Verifikasi oleh Admin
sequenceDiagram
    autonumber
    actor Admin as Admin
    participant Browser as Browser
    participant Detail as detail.php
    participant DB as Database

    Admin->>Browser: Buka Daftar SPPD
    Browser->>Detail: GET /pages/sppd/daftar.php
    Detail->>DB: SELECT tb_sppd (status = 'diajukan')
    DB-->>Detail: Daftar SPPD menunggu verifikasi
    Detail-->>Browser: Tampilkan daftar SPPD

    Admin->>Browser: Klik "Detail" pada SPPD
    Browser->>Detail: GET /pages/sppd/detail.php?id=X
    Detail->>DB: SELECT data lengkap SPPD
    Detail-->>Browser: Tampilkan detail SPPD

    Admin->>Browser: Klik "Verifikasi & Teruskan ke Pimpinan"
    Browser->>Detail: POST (action=verifikasi)
    Detail->>DB: UPDATE tb_sppd SET status='diverifikasi' WHERE id_sppd=X
    DB-->>Detail: Berhasil diupdate
    Detail->>Browser: Redirect ke detail.php
    Browser-->>Admin: Status berubah menjadi "Diverifikasi"
4. Persetujuan oleh Pimpinan
sequenceDiagram
    autonumber
    actor Pimpinan as Pimpinan
    participant Browser as Browser
    participant Approval as approval.php / detail.php
    participant DB as Database

    Pimpinan->>Browser: Buka Halaman Persetujuan
    Browser->>Approval: GET /pages/sppd/approval.php
    Approval->>DB: SELECT tb_sppd WHERE status = 'diverifikasi'
    DB-->>Approval: Daftar SPPD menunggu keputusan
    Approval-->>Browser: Tampilkan daftar SPPD

    alt Setujui SPPD
        Pimpinan->>Browser: Klik "Setujui"
        Browser->>Approval: POST (id_sppd, keputusan=setuju)
        Approval->>DB: UPDATE tb_sppd SET status='disetujui', id_pimpinan=?, tgl_persetujuan=NOW()
        DB-->>Approval: Berhasil diupdate
        Approval->>Browser: Redirect / tampilkan pesan sukses
        Browser-->>Pimpinan: Status berubah menjadi "Disetujui"
    else Tolak SPPD
        Pimpinan->>Browser: Klik "Tolak" → Isi alasan penolakan
        Browser->>Approval: POST (id_sppd, keputusan=tolak, catatan_tolak=...)
        Approval->>DB: UPDATE tb_sppd SET status='ditolak', catatan_tolak=?
        DB-->>Approval: Berhasil diupdate
        Approval->>Browser: Redirect / tampilkan pesan sukses
        Browser-->>Pimpinan: Status berubah menjadi "Ditolak"
    end
5. Kelola SPPD — Anggota, Laporan, & Biaya
sequenceDiagram
    autonumber
    actor User as Pegawai / Admin
    participant Browser as Browser
    participant Kelola as kelola.php
    participant DB as Database

    User->>Browser: Buka Kelola SPPD
    Browser->>Kelola: GET /pages/sppd/kelola.php?id=X
    Kelola->>DB: SELECT data SPPD, anggota, laporan, biaya
    DB-->>Kelola: Data lengkap
    Kelola-->>Browser: Tampilkan tab (Anggota / Laporan / Biaya)

    note over User, DB: Tab 1 — Tambah Anggota Rombongan
    User->>Browser: Pilih pegawai & peran, klik "Tambah Anggota"
    Browser->>Kelola: POST (action=tambah_anggota, id_pegawai, peran)
    Kelola->>DB: INSERT INTO tb_sppd_anggota
    DB-->>Kelola: Berhasil
    Kelola->>Browser: Refresh halaman
    Browser-->>User: Anggota ditambahkan

    note over User, DB: Tab 2 — Simpan Laporan Hasil Dinas
    User->>Browser: Isi form laporan + upload bukti
    Browser->>Kelola: POST (action=simpan_laporan, tgl_aktual, uraian, kesimpulan, bukti_file)
    Kelola->>DB: INSERT/UPDATE tb_laporan_dinas
    Kelola->>DB: UPDATE tb_sppd SET status='selesai'
    DB-->>Kelola: Berhasil
    Kelola-->>User: Laporan tersimpan, status = Selesai

    note over User, DB: Tab 3 — Tambah Biaya Realisasi
    User->>Browser: Pilih komponen biaya, isi jumlah hari & besaran, upload kwitansi
    Browser->>Kelola: POST (action=simpan_biaya, id_komponen, jumlah_hari, besaran, kwitansi)
    Kelola->>DB: INSERT INTO tb_biaya_perjalanan
    DB-->>Kelola: Berhasil
    Kelola-->>User: Biaya ditambahkan
